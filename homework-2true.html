Homework 2

Encryption, Decryption and Statistical Cryptanalysis

1. Introduction

The objective of this homework is to investigate encryption, decryption, and cryptanalysis using two different cryptographic constructions: a toy elliptic-curve encryption scheme and the classical Caesar cipher.

We first encrypt and decrypt the same message using both algorithms. We then compare their procedures, key spaces, and statistical properties. Finally, we implement attacks that exploit the specific weaknesses of each construction.

The previous homework introduced the secp256k1 elliptic curve and the public-key relationship Q = dG. Its interactive demonstration used a much smaller educational curve:

y² = x³ + 7 (mod 17)
G = (1, 5)
d ∈ {1, 2, ..., 8}

We reuse this small curve to make the encryption and key-recovery experiments computationally transparent. It is important to distinguish this educational construction from a secure implementation of secp256k1.

2. Elliptic-Curve Encryption and Decryption

We implement a simplified ECIES-like hybrid encryption scheme. The recipient generates a private scalar d and its corresponding public key Q:

Q = dG

The sender uses the recipient's public key and selects an ephemeral scalar r. The following two elliptic-curve points are computed:

R = rG
S = rQ

The point R can be transmitted publicly. The point S represents the shared secret used to derive a byte mask for encrypting the message.

The recipient uses the private key d to reconstruct the same shared point:

S = dR = d(rG) = r(dG) = rQ

In our toy implementation, each plaintext byte is XORed with a deterministic mask generated from the coordinates of S. Decryption applies the same XOR operation again.

Cᵢ = Mᵢ XOR mask(S, i)
Mᵢ = Cᵢ XOR mask(S, i)

This mask is intentionally simple and insecure. A real encryption scheme would require a secure key-derivation function, authenticated encryption, and carefully generated randomness.

Experiment A — ECC Encryption

2.1 Role of the Keys

The private key d is known only to the recipient. The corresponding public key Q can be distributed to anyone who wants to encrypt a message.

The ephemeral scalar r is selected by the sender and determines the temporary public point R. The shared point S can then be obtained by the sender using r and Q, or by the recipient using d and R.

In a properly designed elliptic-curve encryption system, the private key must be sufficiently large and randomly generated. In this experiment, the private-key range contains only eight possible values, making exhaustive search trivial.

3. The Caesar Cipher

The Caesar cipher is a classical substitution cipher that shifts every letter of the alphabet by a fixed integer k.

For an alphabet containing 26 letters, encryption and decryption can be expressed as:

Eₖ(x) = (x + k) mod 26
Dₖ(y) = (y − k) mod 26

Unlike the elliptic-curve construction, Caesar is a symmetric-key cipher: the same shift k is used for encryption and decryption.

In our implementation, uppercase and lowercase letters are preserved and nonalphabetic characters remain unchanged.

The Caesar cipher preserves the relative frequency of letters because every occurrence of a given letter is always mapped to the same ciphertext letter.

The ECC-based toy scheme instead operates on message bytes through a shared-secret-derived mask. However, the simple mask used in this experiment does not provide the security properties of a properly designed encryption algorithm.

5. Statistical Cryptanalysis of Caesar

Natural languages have characteristic statistical distributions of letters. For example, the letters E, T, A, and O appear relatively frequently in ordinary English text, while letters such as Q, X, and Z appear less often.

A Caesar cipher does not destroy these frequencies. It simply rotates their positions in the alphabet. This property allows an attacker to estimate the unknown encryption shift.

5.1 Frequency Analysis

Our attack tests every candidate shift from 0 to 25. For each candidate, it decrypts the ciphertext and calculates how closely the resulting letter distribution matches the expected English frequencies.

We use the chi-square statistic:

χ²(k) = Σ [ (Oᵢ(k) − Npᵢ)² / (Npᵢ) ]

Here, Oᵢ(k) is the observed frequency count of letter i after decrypting with shift k, N is the number of alphabetic characters, and pᵢ represents the expected relative frequency of that letter in English.

The shift producing the smallest chi-square statistic is selected as the most likely key.

Observations and Limitations

Statistical cryptanalysis generally becomes more reliable as more ciphertext is available, but its effectiveness also depends on how representative the plaintext is of the reference language.

Short messages, unusual vocabulary, repetitive text, and texts in a different language can produce incorrect key estimates.

The Caesar cipher also has a very small key space, so exhaustive search is always practical. N-gram scoring could improve candidate ranking, especially for some shorter messages.

6. Recovering the ECC Private Key

We now investigate an attack against the restricted private-key range of the educational elliptic-curve scheme.

The attacker knows the public key:

Q = dG

Because d can only take values from 1 to 8, the attacker can simply calculate:

G, 2G, 3G, ..., 8G

The candidate matching Q reveals the private scalar d. Once d is recovered, the attacker can compute the shared point using the transmitted ephemeral public point R:

S = dR

The attacker can then reconstruct the byte mask and decrypt the intercepted ciphertext.

6.1 Why the Attack Works

The vulnerability is caused by the restricted private-key space. An attacker only needs to test eight possible private scalars to find the correct one.

The attack does not require any statistical information about the plaintext. It relies entirely on the mathematical relationship between the public and private keys.

6.2 Why Real ECC Is Different

In a properly configured secp256k1 system, private keys are selected from a group of order approximately 2²⁵⁶.

Trying every possible private key is therefore computationally infeasible. Generic discrete-logarithm algorithms such as Pollard's rho still require approximately 2¹²⁸ group operations.

Importantly, even if a real secp256k1 curve were used, restricting its private keys to only eight possible values would make the same exhaustive attack practical.

Therefore, the security problem is not simply the choice of elliptic curve, but the combination of curve parameters, key generation, entropy, and encryption design.

8. Conclusions

These experiments illustrate two fundamentally different forms of cryptanalysis.

The Caesar cipher can be attacked by exploiting the statistical redundancy of natural language. Its substitution operation preserves letter frequencies, allowing the shift to be estimated using a reference distribution.

The toy elliptic-curve scheme is vulnerable because the private-key range is extremely small. The attacker can recover the key by computing all possible public points and comparing them with the known public key.

While increasing the ciphertext length generally helps statistical analysis of Caesar, the exhaustive ECC attack depends primarily on the number of possible private keys.

The main lesson is that cryptographic security depends not only on the mathematical algorithm, but also on key-space size, secure randomness, implementation choices, and protocol design.
