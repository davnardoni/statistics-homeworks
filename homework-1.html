Homework 1.1

Public-Key Cryptography: From Private Key to Public Key

1. Introduction

Public-key cryptography is based on two mathematically related keys: a private key, which must remain secret, and a public key, which can be shared with other users. These keys are used in cryptographic systems to perform operations such as digital signatures and verification.

Ethereum uses Elliptic-Curve Cryptography (ECC), specifically the secp256k1 elliptic curve. In ECC, a public key is generated from a private key through an operation called scalar multiplication:

Q = kG

Here, k is the private key, G is a publicly known base point on the elliptic curve, and Q is the resulting public key. Scalar multiplication means repeatedly adding the base point G according to the scalar k.

This operation is deterministic: the same private key and base point always produce the same public key. Moreover, it is computationally efficient in the forward direction. However, for appropriately chosen cryptographic parameters, recovering k from Q is computationally difficult. This is the Elliptic Curve Discrete Logarithm Problem (ECDLP).

Scalar multiplication therefore shares the hard-to-reverse characteristic of cryptographic one-way functions. However, it is not a cryptographic hash function: it has a specific algebraic structure and is primarily used in public-key cryptography.

The goal of this homework is to implement scalar multiplication in JavaScript using a small elliptic curve, visualize the intermediate steps, and investigate the statistical properties of the resulting public points.

2. The Toy Elliptic Curve

Real cryptographic curves operate over very large finite fields. To make the calculations easier to understand, this experiment uses the following small elliptic curve:

y² ≡ x³ + 7 (mod 17)

The modulus 17 means that all calculations take place in the finite field F17, so the coordinates of each finite point are integers between 0 and 16. A point belongs to the curve if its coordinates satisfy the equation.

We choose the base point G = (1, 5). We can verify that this point belongs to the curve:

5² mod 17 = 8
(1³ + 7) mod 17 = 8

Since the two expressions are equal, G is a valid point on our elliptic curve.

Point Addition and Point Doubling

To calculate kG, we need to add points on the curve. If P = (x₁, y₁) and R = (x₂, y₂) are distinct points with different x coordinates, their sum is obtained using a slope λ:

λ = (y₂ − y₁)(x₂ − x₁)⁻¹ mod 17

If we add a point to itself, we perform point doubling, using:

λ = 3x₁²(2y₁)⁻¹ mod 17

In both cases, the resulting point has coordinates:

x₃ = (λ² − x₁ − x₂) mod 17
y₃ = (λ(x₁ − x₃) − y₁) mod 17

The inverse symbol refers to a modular multiplicative inverse, not ordinary division. The special point at infinity, denoted by O, acts as the identity of point addition.

For example, starting from G = (1, 5), we can calculate 2G by point doubling. The inverse of 10 modulo 17 is 12, so λ = 3 × 12 mod 17 = 2. Substituting into the coordinate formulas gives 2G = (2, 10). We can then calculate 3G = 2G + G, and continue until reaching kG.

Observations

With k = 6, the program produces the public point Q = (5, 8). An interesting characteristic is that the base point has order 9, meaning that 9G = O and 10G = G. Consequently, the generated sequence is periodic.

This makes the toy curve insecure: a possible private key can be recovered by trying a very small number of values. In real cryptographic systems, a base point with a sufficiently large prime order is used to make this kind of attack computationally infeasible.

4. Statistical Exploration

To study the properties of elliptic-curve scalar multiplication, we repeat the experiment for all eight private keys in the subgroup: k = 1, 2, ..., 8.

For each input, we collect its public point, examine the coordinate frequencies, investigate the binary representations, and compare the inputs with their corresponding outputs.

4.1 Distribution of Coordinates

The first experiment analyzes the frequency of the x and y coordinates of the generated public points. A uniform distribution would assign the same frequency to each possible coordinate value.

However, elliptic-curve coordinates are constrained by the curve equation, and not every field element needs to appear equally often in the selected subgroup.

Y-coordinate frequencies

The x coordinates are repeated in pairs because opposite points P and -P have the same x coordinate. The y coordinates in our sample are all different.

Therefore, the coordinates are not uniformly distributed over the entire finite field. An apparently balanced distribution over only the observed values should not be confused with randomness or cryptographic security.

4.2 Bit Distribution

Each coordinate is an integer between 0 and 16 and can be represented using five binary digits. We count the number of zero and one bits in all generated x and y coordinates.

For cryptographic applications, balanced bit distributions can be an interesting statistical property. Nevertheless, the presence of approximately equal numbers of zeros and ones does not prove that a function is secure or computationally difficult to invert.

Our experiment contains only eight finite public points, so these frequencies are descriptive rather than evidence about the randomness of real elliptic-curve cryptography.

4.3 Input-Output Correlation

We now investigate whether the numerical value of the private key is linearly related to either coordinate of the public key. For this purpose, we use Pearson's correlation coefficient.

A correlation close to zero indicates little linear association between the quantities being compared. However, it does not exclude nonlinear or algebraic relationships.

In fact, elliptic-curve multiplication has a well-defined algebraic structure. Even if the observed correlation is zero, it does not follow that the private key cannot be recovered.

4.4 Avalanche-like Behaviour

A desirable property of cryptographic hash functions is the avalanche effect: changing a small part of the input should produce substantial changes in the output bits.

We explore similar behaviour by comparing the binary coordinates of public points generated from consecutive private keys. The Hamming distance measures how many corresponding output bits are different.

Since we use two 5-bit coordinates, each public point is represented by ten bits for this experiment. A Hamming distance of 5 therefore means that half of the output bits have changed.

It is important to note that consecutive integer keys do not always differ by only one bit. Therefore, this is an illustrative avalanche-like experiment, not a formal test of the strict avalanche criterion.

Furthermore, the avalanche effect is mainly a desirable property of cryptographic hash functions and block ciphers, rather than a primary security requirement for elliptic-curve scalar multiplication.

5. Discussion and Conclusions

The experiment demonstrates that elliptic-curve scalar multiplication is a deterministic mathematical operation that transforms a private scalar into a public curve point. The same input always generates the same output, and the forward computation can be performed efficiently.

The statistical exploration shows that the generated points have observable coordinate frequencies, bit distributions and input-output relationships. However, these simple statistical properties do not directly measure one-wayness.

One-Way Functions and Cryptographic Hashes

Although scalar multiplication and cryptographic hash functions share some characteristics, they are designed for different purposes.

Property ECC Scalar Multiplication Cryptographic Hash
Deterministic Yes Yes
Forward computation Efficient Efficient
Hard to invert Based on ECDLP Preimage resistance
Output Curve point Fixed-length bit string
Algebraic structure Group operation No comparable requirement
Avalanche property Not a main requirement Desirable
Typical purpose Public-key cryptography Hashing and integrity

In particular, elliptic-curve multiplication preserves the relation:

(a + b)G = aG + bG

This algebraic relationship is fundamental to elliptic-curve cryptography and digital signature algorithms, while cryptographic hash functions generally seek to avoid predictable relationships between inputs and outputs.

Conclusion

Using the curve y² = x³ + 7 (mod 17), the base point G = (1, 5), and the private key k = 6, we obtained the toy public key Q = (5, 8).

The experiment helped illustrate scalar multiplication, repeated point addition and the mathematical relationship between private and public keys.

It also highlighted why simple statistical properties, such as coordinate uniformity, bit balance or low correlation, are not sufficient to establish cryptographic security. The real security of appropriately chosen ECC systems relies on the computational difficulty of the Elliptic Curve Discrete Logarithm Problem.
